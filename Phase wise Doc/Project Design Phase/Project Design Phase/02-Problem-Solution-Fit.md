# Problem–Solution Fit

| Problem / need | iMovies response |
|---|---|
| Movie and show details are spread across separate sources | Movie listing, detail and showtime pages |
| Users need to check seats before booking | Seat map and seat status API |
| Seats should not be booked twice | Per-show seat records, unique index and hold workflow |
| Users need a record of their bookings | Booking list, details and status |
| Booking may be abandoned before payment | Temporary holds expire and are cleaned up |
| Admin needs to maintain catalogue data | Admin movie, theatre and screen operations |
| Admin needs to maintain show schedules | Admin show list/create/update operations |
| Admin needs booking oversight | Booking search/filter and cancellation tools |

This table describes intended fit, not the results of a formal customer study.
